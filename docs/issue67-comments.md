# Issue #67：评论指令核验

规格以 [Issue #67 正文](https://github.com/simonjiao/gongcao/issues/67) 为准，基于
已合并的 #57、#56。只调整既有 `Controls.collect/issue/apply_pending` 与核验查询，
复用 SQLite `instructions`，不改表结构或阶段机。

- 新指令按任务内尚未登记的评论 ID 接收，时间只供审计。同秒和首次读到的历史评论
  都按当前事实绑定阶段、SHA、需求基线，并在应用时重新校验；消费仍与阶段迁移同事务。
- 首次已编辑评论拒绝；已登记评论的编辑、指纹或作者变化记为 `stale`。后续到达检查点
  不会把失效记录覆盖成 `consumed`，也不重新受理相同 ID。
- 完整分页成功后，对缺失的待消费/有效授权评论按 ID 直读；直读仍可见时使用其事实核验。
  分页失败、403、不明 404 或直读异常均持久保留 `Instruction verification pending`，
  在安全点暂停，不允许旧许可启动下一阶段或远端写入。
- GitHub 的 404 可能掩盖权限问题，不能独立证明删除。因此删除后持续返回 404 的评论
  保留待核对原因，而不记录未经证明的“已删除”结论。其有效执行许可仍被暂停。
  未消费评论恢复可见且原文核验通过后可应用；已生效许可一旦暂停，需新指令恢复。
  本地显式指令可替代此前尚未消费的评论，包括待核对评论。
- 多条冲突指令按评论 ID 识别，跨秒也保守暂停。已开始的工作按原边界收束，保留
  未知写入、租约、SHA/需求失效及单步消费约束；已终结任务不会因评论变化重启。
  配置摘要变化仍按原有规则失效并重建质量证据。
- 同一任务的前台/后台收集共用 OS 文件锁，跨 Store/进程串行读取及登记，避免旧查询
  或失败查询与并发登记交错，绕过消费前核验。取消或进程退出会释放锁，不占用 Agent 租约。

GitHub 状态码依据：[评论读取 API](https://docs.github.com/en/rest/issues/comments#get-an-issue-comment)、
[404 与鉴权](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api#404-not-found-for-an-existing-resource)。

## 差异化验证

`uv run pytest -q tests/test_control.py -k unseen_comment_ids` 在修复前稳定失败两例：
同秒评论与首次发现的历史评论均错误停在 `waiting_instruction`。修复后的回归包括：

- 同秒接收、历史评论按当前事实校验、登记后 SHA 变化拒绝、消费事务及重启不重放。
- 首次编辑拒绝；原文指纹、编辑时间与作者变化分别核验；失效 step 到达检查点仍为 stale。
- 首次已编辑评论重复扫描仍为 rejected；前台分页失败与另一 Store 并发登记不能误消费。
- 待消费/有效授权两种状态下的删除、分页中断和暂时列表缺失；缺失时按 ID 直读。
- 待核对原因跨重启保留，成功复核与本地显式替代两条恢复路径。
- 已完成任务的编辑/删除/查询失败不会重新激活；跨秒冲突保守暂停。
- Agent 返回期间的暂停、修订、删除及查询失败均阻止随后的发布；在途写入仍按既有测试收束。
- 离线 CLI 直接使用检查点所在秒的时间戳，去掉跨秒等待，确认一次发布及重启不重放。

`qa/copilot.py` 去掉发布指令前的跨秒等待，以删除待消费评论替代旧的“时间过期”探针。
保留首次编辑探针为观察 GitHub 编辑时间而等待的必要时间；场景版本为 7。
这些协议替身测试不构成真实 GitHub/模型验收。

规模：正式代码 +105/-28，内部测试 +213/-6，CLI +1/-2，QA +23/-10，另有文档。
代码量超过非硬性估计，新增串行收集以消除前台/后台核验竞态；内部测试覆盖了待消费与
有效授权、重启、终态、跨 Store 并发、Agent 返回后发布及事务内 stale 保留这些不同边界。

## 调度与依赖

`serve` 在前台轮询已登记的任务，默认并发 1，可选 1–3。共享状态目录的控制器合计最多占用
三个执行租约；同一任务使用 OS 文件锁，同一仓库/分支和规范化 GitHub 对象也只能有一个占用者。
仓库大小写别名被统一处理，分支名保留大小写。新 Issue 的分支在创建 PR 前已经确定并占用，
因此“PR 创建成功、本地尚未关联”的窗口也保留分支占用。

`depend TASK --on OTHER` 添加依赖，依赖须由 GitHub 确认已合并；可合并状态尚不能解锁依赖。
循环依赖在事务中拒绝并回滚，`depend TASK --clear` 清除依赖。依赖或执行容量不足时显示等待原因，
不消耗执行重试预算。若依赖合并使未发布 Issue 的登记基线过时，人工执行
`retry TASK --refresh-base` 从远端默认分支重新分析；已存在远端写入意图的任务不能这样换基线。

执行或环境失败最多自动尝试三次，前两次失败后分别退避 10/20 秒，第三次转人工。CI 等待和普通日志静默
不算执行失败；代码修订另受已有 max_revisions 限制。`diagnose` 展示租约、进程记录、依赖、
失败重试信息以及重复失败、执行超时和有限尝试仍无进展等规则结果，不做 AI 日志诊断。

## 进程、租约与恢复

租约记录所有者 UUID、PID、Linux boot ID/进程启动时间、资源和期限，定期续约。
阶段/证据写入核验所有者，旧所有者的迟到结果不能通过。租约过期本身不允许抢占：
恢复仍须取得 OS 文件锁。调度器停止时先停止并 join 活跃执行，留下可核对状态；显式 cancel 保持取消。

子进程启动前记录意图，取得 PID 后记录身份。正常结束确认收尾；硬中断遗留的模型/质量沙箱，
结合受控 PID namespace、父进程死亡约束和进程/会话事实核对。泛用 Git/GitHub helper 的中断、
缺少 PID 的启动窗口及 CleanupError 均不能仅凭原 SID 消失自动清除；同次开机中保留待核对。
明确的新 boot ID 可以证明旧开机进程已不存在。程序不会按可能复用的 PID 盲目杀进程。

`recover TASK` 只读查询 GitHub/分支并核对已记录的会话引用、上下文哈希、工作区 HEAD、租约和进程。
仅接受原始目标或带本 Run 标记且父节点正确的控制器提交。中断的模型运行失效，重试创建新线程及
新 Worktree，旧线程标识和部分工作文件保留。已完成但结果 SHA 错误的记录也失效，缓存入口再次核验。

远端意图必须被稳定标识、SHA、PR/评审事实确认才记成功；没有看到结果时不重发。
可确认的草稿 PR 会重新关联，再按当前 GitHub 版本建立门禁。未结进程或远端意图保留资源占用，
另一登记对象也不能绕过。无法确认时保持待核对，需要操作者排查或进一步独立证据。

`retry TASK` 先执行核对，再允许人工重试；检查缓存及审查/验证运行证据失效，保留历史和已确认的
开发输出，以免重新发布另一个提交。只有显式 `--reset-revisions` 才重置自动修订预算。
关闭、取消和已合并任务不能借 retry 复活；重新打开后仍须显式人工重试。

## 存储与日志

SQLite 模式在事务内由 0→1→2 升级，保留任务、运行、事件、artifact 和 intent 历史。
第二阶段的旧 active run 没有可靠进程身份时不会自动恢复；未来版本数据库拒绝打开。
`inspect` 包含运行、受控写入和运行时诊断；`logs --run RUN --kind KIND --contains TEXT` 搜索
该任务已脱敏的保留日志，也支持 follow。每 Run 保留两份受限 JSONL 和最多 1000 条事件索引。
每任务最多保留 1000 条已停止进程记录，未结进程和远端意图不因保留上限而删除。

协调范围是同一 state-dir；多个独立状态目录不能并行管理同一 GitHub 对象。
继续使用 Linux + Bubblewrap、可信任务代码边界。控制器只发布分支、PR 和 COMMENT，不自动合并或发布。
生产代码超过原先 1,700–2,900 行初估，新增部分用于持久化进程身份、跨进程占用及只读核对，
没有引入外部调度框架、数据库服务或项目管理界面。
